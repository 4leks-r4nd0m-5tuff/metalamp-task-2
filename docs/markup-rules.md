# Markup Rules (Metalamp Frontend Task)

Этот документ описывает правила верстки для проекта:
UI Kit + страницы поиска номеров отеля.

Цель — понятная, предсказуемая и переиспользуемая верстка.

---

## 1. Общий подход

- Используется методология БЭМ
- Верстка строится из независимых компонентов (blocks)
- Каждый компонент переиспользуется
- Используются семантические HTML-теги
- Верстка адаптивна (320px – 1920px)
- Inline-стили не используются

---

## 2. Структура проекта

```
src/
blocks/   # компоненты (БЭМ-блоки)
pages/    # страницы (ui-kit, search pages)
styles/   # глобальные стили (минимальные)
assets/   # изображения, шрифты
```

---

## 3. Компоненты (blocks)

### Как создается компонент

1. Создать папку в `blocks/`
2. Добавить файлы:
   - `block.pug`
   - `block.scss`
   - `block.js` (если нужна логика)
3. Разметка пишется по БЭМ
4. Стили пишутся внутри блока
5. Подключение через Pug `include`

---

### Правила компонентов

- 1 блок = 1 папка
- Блок независим от страницы
- Нельзя смешивать стили разных блоков
- Состояния делаются через модификаторы:
  - `block--active`
  - `block--disabled`

---

## 4. UI Kit (главная страница компонентов)

UI Kit — это страница, где собраны все компоненты проекта.

### Как работает UI Kit:

- Сначала создаются все компоненты (blocks)
- Затем они подключаются на страницу UI Kit
- Каждый компонент показывается в разных состояниях

### Пример подключения:

```pug
include ../blocks/button/button.pug
include ../blocks/input/input.pug
```

---

## 5. Использование компонентов на страницах

После UI Kit те же компоненты используются на страницах:

* поиск номеров
* карточки отелей
* фильтры

Компоненты не дублируются — только переиспользуются.

---

## 6. HTML правила

* Используются семантические теги: header, main, section, nav, footer, article
* Каждый элемент имеет осмысленную структуру
* Все классы только по БЭМ
* div используется только если нет семантической альтернативы
* Все изображения должны иметь `alt` с описанием содержимого
* Ссылки на чужие сайты должны содержать атрибут target="_blank", чтобы открываться в новом окне
* Все ссылки с target="_blank" должны так же содержать атрибут rel="noreferrer"

---

## 7. SCSS правила

* Каждый блок имеет свой файл стилей
* Глобальные стили минимальны

Запрещено:

* `!important`
* глобальные селекторы (div, h1, button)
* дублирование стилей между блоками

---

### Вложенность

Максимум 2 уровня:

```scss
.button {
  &--primary {
    background: black;
  }

  &__text {
    padding: 8px;
  }
}
```

---

## 8. Цель

* Чистая компонентная структура
* Переиспользуемые блоки
* Простая поддержка верстки
* Отсутствие дублирования кода
* Соответствие макету Figma
